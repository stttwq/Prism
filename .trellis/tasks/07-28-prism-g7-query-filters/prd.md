# G7 `ext:` 与 `path:` 查询过滤

## Goal

在不扩张为复杂查询语言的前提下，增加可组合的 `ext:` 与 `path:` 过滤，并保证过滤发生在 Top-K 前，不因先截断后过滤漏掉合法结果。

## Requirements

- 强依赖 G1 的全局 Top-K、稳定协议和前端测试地基。
- 普通 token 继续作为名称查询；`ext:` 值用逗号表达 OR；多个不同过滤器、重复过滤器和可选 root 之间取 AND。
- `path:` 对规范化完整路径做 Windows 不区分大小写的字面子串匹配；带空格值必须使用双引号。
- extension 规范化时忽略一个前导点并不区分大小写；目录没有扩展名，除非规范明确匹配空值，本任务不支持空值匹配。
- 未识别、不完整、未闭合引号或空过滤 token 按普通文本处理，不能静默丢失用户输入。
- 有有效过滤器时只返回文件/文件夹，不混入应用、窗口或网页结果。
- broker 解析为结构化 filters；indexer 校验条数/长度并在候选进入 Top-K 前应用。
- `ext:` 使用名称元数据过滤；`path:` 在名称候选通过后用有界最终路径/父链信息判断，但仍必须先过滤再取 Top-K。
- 缓存键包含规范化 filters；过滤器、root 或 mode 变化使增量缓存失效。
- 不实现 `size:`、`datemodified:`、负向过滤、自然语言日期或任意字段扩展。

## Acceptance Criteria

- [ ] 单扩展、多扩展 OR、多个过滤 AND、重复过滤、引号路径、前导点和大小写有解析测试。
- [ ] 空值、未知 token、未闭合引号和不完整过滤均按普通文本保留。
- [ ] root + ext + path 组合在 Top-K 前执行，构造语料证明过滤后仍返回足额 `max=8/1000`。
- [ ] 有过滤器时不返回应用、窗口或网页结果。
- [ ] filter 变化使前端缓存失效，迟到的旧 filter 响应不覆盖新结果。
- [ ] 路径构造/父链验证次数与 G0 基线可解释，三进程内存 ≤100MB，暖 8/1000 门槛满足。
- [ ] Rust tests、Clippy、C# tests 和 WPF Release build 全部通过。

## Out Of Scope

- `size:`、日期、负向过滤、正则、自然语言和内容搜索；
- 自定义查询字段或插件；
- 应用/窗口/网页字段过滤。

## Dependencies

强依赖 G1；若与 G4 root 同时存在，必须遵守 root 与 filters 取 AND 的已定义兼容行为。
