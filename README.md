# Prism

一个藏在 Windows 后台的小助手，Listary 的替代品。你想找文件、开软件、搜网页、切窗口时，敲两下 Ctrl 它就冒出来，一秒内给你答案；用完一挥手它又缩回去，几乎不占地方。

## 它能干什么

- **找文件一秒出结果**：普通搜索要一个文件夹一个文件夹翻，像挨个抽屉找东西。Prism 不一样——它手里攥着整块硬盘的"花名册"（直接读 NTFS 的主文件表，不挨个翻目录），硬盘上每改一个文件，系统还会顺手给它留张便条（USN 日志），所以它永远拿着最新名单。你打几个字，结果马上列出来，几块硬盘的文件一起排、一起比，不按硬盘顺序硬截断。
- **开软件**：开始菜单里的程序它都认得，还留着中文名。打「微信」回车就开。
- **搜网页**：`g 关键词` 用 Google，`b` 百度，`bi` Bing，用默认浏览器打开。想加别的网站，设置里加个关键词就行。你直接打一个网址，它也认得是要开网页，不会傻乎乎当成文件名。
- **拼音找中文**：打 `wx`、`weixin`、`xin` 都能找到「微信」。首字母和全拼都行，还认得多音字；要是拼音表坏了，就老老实实按字面找，不罢工。
- **筛一筛**：加 `ext:pdf,doc` 只要这两类文件，加 `path:"Project Docs"` 只看路径里带这几个字的。筛完只剩文件和文件夹，不夹带软件和网页。
- **一排文件操作**：找着文件后按方向键展开操作——打开它所在的文件夹、复制剪切、复制路径、重命名、复制到…、移动到…、扔进回收站、永久删除、压成 ZIP、看属性、用别的程序打开、或调出系统右键菜单。复制到/移动到会让你再挑个去处。删文件该弹的确认照弹，绝不偷偷下手。
- **每个动作能绑快捷键**：比如想让复制路径是 Ctrl+Shift+C，自己绑一个。但方向键、回车、Esc 这些"保命键"永远比你的绑定优先，怎么自定义都不会把导航弄废。
- **暂存条和工作集**：搜索框底下有条小条子，能搁几个待处理的文件，放满了把最旧的挤掉。想攒一整组？存成命名工作集，以后打这名字回车就整组回来，还能整组拖到别的程序里。
- **越用越懂你**：你开过、定位过的东西会被记住，下次更靠前——但只在"同一档"里加权，拼音的弱命中不会压过字面的强命中。觉得它学歪了，一键清空，也能干脆关掉。
- **只搜当前文件夹**：从资源管理器或 Directory Opus 里把它叫出来时，可以限定只看当前文件夹（连子文件夹），Ctrl+G 在"只看这里"和"看全局"之间切。要是没认出当前在哪个文件夹，立刻退回全局，不会拿上次那个糊弄你。
- **切窗口**：打 `>` 进入窗口模式，按标题和应用名匹配当前开着的窗口。它自己的窗口、后台工具窗、别的虚拟桌面上的窗口都过滤掉。认窗口靠的是临时"号牌"，不出手给你，切之前再核一遍号牌还在不在。
- **给文件起外号**：给某个文件/文件夹/程序绑个词，打这个词就直达它。
- **联网建议**：默认关着。开了之后会顺手问 Bing/百度/Google "你大概是想搜这个吧"，800ms 内没回就拉倒，你改主意它就取消旧请求，而且不记进历史。
- **随叫随到**：默认连按两下 Ctrl 冒出来，也能改成别的组合键。搜索框弹在屏幕正中，按 Esc 或点别处就缩回去。
- **跟着系统换皮**：Windows 切深色它就深色，切浅色它就浅色。

## 为什么好用

- **几乎不占内存**：三个常驻程序加起来的内存被死死摁在 100MB 以内。它怎么做到的？文件名单不一条条存全名，而是把所有名字挤进一根长条里，每个文件只记"从哪到哪"两个字段（省下大半空间）；图标按文件类型共用一份、窗口一缩就放手；打包配置优先速度而非体积（release 档 opt-level=3），体积换响应。
- **找得快**：靠主文件表和 USN 日记这对组合拳，第一次建完索引后，硬盘一有改动秒级就感知到。
- **装完就能用**：系统盘先建完先可搜，别的盘在后台继续建、还显示进度，装完不会卡在"什么都搜不了"的空窗期。
- **该高的高，该低的低**：建索引这种重活交给系统服务用最高权限去干，但点按钮、复制文件、上网、改设置这些活儿留在你自己这个普通用户的身份下做——手别伸太长。接资源管理器和 Directory Opus 也是走人家官方的大门，不偷偷往里塞东西（不搞 DLL 注入）。
- **不怕坏**：它存的所有东西都带着版本号，写一半断了会重写，真坏了就耸耸肩重建——你的数据、你的设置一点不丢。
- **动作就那几样**：能干的事是一张写死的清单，没法被"发明"出新的危险动作；真要动手前还会再确认一遍目标还在不在、是不是对得上类型。
- **不给你过期的答案**：每搜一次都带个序号，你打字快、旧答案还没回来就作废，绝不会拿上一秒的查询盖住这一秒的。索引一改也跟着翻号，缓存带号，对不上号就重算。
- **联网默认守口如瓶**：在线建议和网站图标默认都关着，图标还要你一个一个网站点头才去取，建议不进历史，网络请求还卡着大小和超时上限。
- **快捷键不罢工**：快捷键监听跑在独立的一条线程上，界面再忙也不漏键；万一被 Windows 误杀了，60 秒后自己爬起来重装。

## 平台和搭档

- **系统**：只在 Windows 11 x64 上跑，需要 .NET 8 运行时。Windows 10、ARM 机器、老 x86 不在承诺范围内。
- **能联动的文件管理器**：Windows 资源管理器、Directory Opus 13.23。两个都默认关着，算实验功能，要在设置里手动开。系统的打开/保存对话框暂时不联动，会回退到全局。
- **语言**：界面、安装向导、动作菜单全是简体中文，拼音搜索是内建的本事不是后加的。英文文件名和软件名照样能搜。

## 开发

克隆下来之后，跑一次 `sh scripts/setup.sh`（在 Git Bash 里），它会替你把 git 的 pre-commit 钩子指到仓库里的 `scripts/hooks/pre-commit`，并顺带检查 Rust 工具链在不在。这个钩子只拦一件事：你 `git add` 进去的 `.rs` 文件要是没跑过 `rustfmt`，提交会被挡下来，让你格式化完再提交——但历史代码漂移不株连，只查你这次改的那几个文件。急用时 `git commit --no-verify` 能绕过。钩子靠 `core.hooksPath` 生效，这是本地 git 配置，不随仓库传播，所以每台新克隆的机器都要跑一次 setup。

代码格式统一靠 `rustfmt.toml`（锁 `edition = "2021"`）+ pre-commit 钩子守门。历史上格式漂移过四次，每次都因无强制机制复发；2026-08-22 这次一次性清洗（纯空白/换行/import 顺序，零功能改动）后配了守门，此后不再漂移。用 `git blame` 查功能历史时，建议跳过那次纯格式提交：

```
git blame --ignore-rev 73f1676 -- src/prism-core/src/ipc.rs
```
