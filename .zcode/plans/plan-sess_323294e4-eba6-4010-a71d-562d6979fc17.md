### 方案设计参考：Everything 与 Listary 的启发

调研了 Everything（voidtools）与 Listary（Channing Boge）的索引服务架构，与本批次的实际代码对照：

- **Everything**：1.x 用读锁 + 写时复制的快照搜索，设置开关由 IPC 命令显式下发（`Everything_SetMatchWholeWord` 等），搜索路径**只读**索引，不写开关。这印证了批次 5 的 M6 修正方向——Search 只读、开关走显式命令。Everything 对 USN/MFT 枚举的结束条件靠 `ERROR_HANDLE_EOF`/`ERROR_NO_MORE_FILES` 正常退出，错误则记入卷级失败表并降级——正是 M1 修正的语义。
- **Listary**：6.x 的索引器对单个卷失败采用“跳过该卷 + 降级服务 + 延迟重试”，整体不崩；拼音开关是运行时持久化设置，切换走配置 API 而非通过“空查询”触发。同样印证了 M4（显式命令）和 M1（卷级降级）的方向。
- **共同点**：两者都不让搜索请求写设置，都不用“空查询 side-channel”。这强化了计划中已修正的 M4/M6 设计。两者对枚举错误也都区分“正常结束”与“真实错误”——印证了计划对审计 M1 原始处方的 EOF 特判修正。

结论：批次 5 的设计方向与两个成熟产品一致，无需额外改道；按计划已修正的处方实施即可。

### 项 1 — I2：`max_record` 计算改迭代器聚合（ntfs.rs:398-404）

**现状**：`raw_records.iter().map(split_frn).collect::<Result<Vec<_>,_>>()?.into_iter().max()` 先物化整个 `Vec<u32>`（3M 条 × 4B ≈ 12MB）只为取 max。

**改法**：替换为 `try_fold(root_record, |acc, item| item.map(|v| acc.max(v)))`。语义等价（`split_frn` 返回 `Result`，首个坏 FRN 照样短路 `?`），`root_record` 作为初始累加器保留原 `unwrap_or(root_record)` 语义。

**影响面**：仅 `build_volume_with_progress` 一个函数；`split_frn`/`prepare_initial_capacity` 不变；仅有的调用方 `build_volume_reporting`/`build_volume` 不受影响。I1（`records.extend(batch)` 大分配）明确归批次 9，本期不动。

**风险**：极低。

### 项 2 — I4：pinyin sidecar save 改流式写（pinyin_sidecar.rs:265-282）

**现状**：`postcard::to_allocvec(&self.disk)` 在堆上缓冲完整序列化字节，再 `write_all`。

**改法**：抄 `index_cache.rs:56-71` 模板——`BufWriter::with_capacity(256KB, file)` + `postcard::to_io(&self.disk, &mut writer)` + `flush()` + `get_ref().sync_all()` + `drop(writer)` + `atomic_replace`。`use-std` 特性已在 `Cargo.toml:27` 启用（`index_cache::save` 已在用），无需改依赖。

**影响面**：`PinyinSidecar::save` 仅一处生产调用方（`rebuild_pinyin`，indexer_runtime.rs:266）；`delta.is_empty()` 守卫保留；`atomic_replace` + fsync 契约与 `index_cache::save` 对齐。签名不变。

**风险**：低。

### 项 3 — I5：index_cache load 改 `from_io` 消除全字节 Vec（index_cache.rs:32-46）

**现状**：`read_to_end(&mut Vec)` 物化完整文件字节，再 `postcard::from_bytes`，字节+结构双驻留。

**改法（选项 B，低风险，与计划“低”严重度匹配）**：`BufReader::with_capacity(256KB, file)` + `postcard::from_io(&mut reader)`。`from_io` 由已启用的 `use-std` 特性提供。消掉全字节 Vec，只走 256KB 缓冲。

**不取选项 A（mmap）的理由**：pinyin_sidecar 已有私有 `MappedFile`（pinyin_sidecar.rs:703-779），但搬到共享位置会触碰 sidecar 文件；审计定 I5 为“低”，选项 B 已是严格改进。mmap 化归批次 7 的 H2（锁外压缩 + 内存实测）一起评估更合理，避免本期提前引入跨文件重构。

**影响面**：`index_cache::load` 仅一处生产调用方（`load_cached`，indexer_runtime.rs:1023）；`validate(&envelope.state)` 保留；签名不变。pinyin_sidecar 的 load 已是 mmap，不动。

**风险**：低。

### 项 4 — M1：MFT 枚举错误不再静默（ntfs.rs:542-558）

**现状**（关键行 ntfs.rs:555）：
```
Err(_error) if !records.is_empty() => break,   // 静默吞掉任何 IO 错误
Err(error) => return Err(error),
```
任何已收集至少一批的枚举错误都被当作正常结束，无日志、无传播——卷看似完整实则缺文件。

**审计原始处方（已修正）**：审计 M1 原文把这条 `Err(_) => break` 统一当真实错误处理（日志 + 走 degraded），但实施计划明确修正：**`ERROR_HANDLE_EOF`（Win32 38，HRESULT 0x80070026）是 `FSCTL_ENUM_USN_DATA` 的正常结束返回，视为成功结束**；仅其余错误记日志 + `Err` 上抛，接入既有 `failed_volumes`/degraded 链路（indexer_runtime.rs:874-891 的 `initial_build_volume_failed` 分支）。

**改法**：
1. 不改共享的 `ioctl_buffer` 签名（它被 `query_or_create_journal`/`query_journal`/`read_changes`/`replay_until`/`open_volume` 等共用，改签名波及面大）。新增一个轻量辅助 `ioctl_buffer_code`（或让 `ioctl_buffer` 返回 `Result<usize, (String, i32)>`，但只在此一处调用点改用新辅助）返回 `Result<usize, IoctlError { message: String, code: i32 }>`，**仅在 `enumerate_mft` 的 `FSCTL_ENUM_USN_DATA` 调用点使用**。其余 `ioctl_buffer` 调用点不变。
2. `enumerate_mft` 的 `Err` 分支改为：
   - `code` 为 `ERROR_HANDLE_EOF`（0x80070026）→ `break`（正常结束，与原 `Ok(_) => break` 同义）；
   - 其余 → `log!(...)` 记录“MFT enumeration failed on <handle>: <msg> (collected N records)”并 `return Err(error)`。
3. `read_changes`（FSCTL_READ_USN_JOURNAL，靠 0 字节返回表示空闲）**不动**——它的 EOF 语义不同，不能套用同一特判。

**影响面**：`enumerate_mft` 仅一处调用方（`build_volume_with_progress`，ntfs.rs:381）；错误现在会经 `?` 上抛 → `build_volume_reporting_with`（indexer_runtime.rs:1070-1097）会真实重试一次 → 仍失败则进入 `failed_volumes` → 该卷降级，其余卷照常发布。这是审计期望的“卷级降级”行为。既有重试逻辑（`:1085-1096`）现在对真实 MFT 错误会真正重试，而非静默完成。

**风险**：中。主要风险在于 `ioctl_buffer_code` 的错误码提取要正确（HRESULT 0x80070026 低 16 位 = 38）；要保证 `ERROR_HANDLE_EOF` 判定准确，否则会把正常结束的卷误判为失败、反之亦然。补一个单测注入合成错误验证分支。

### 项 5 — M4+M6：拼音开关走显式协议命令（协议 1→2）

**这是本批次唯一跨组件、唯一协议变更项**。审计原始处方把开关当管理命令，实施计划已修正：保留 `Disabled` 语义（用户显式关闭后 maintenance/checkpoint 不重建）。

#### 现状（三处病灶）
1. **M6**（indexer_runtime.rs:505-510）：`search()` 每次调用都 `self.pinyin_enabled.store(pinyin_enabled, Release)`，`false` 则 `release_pinyin()`（丢 sidecar + 置 `Disabled`）。两个偏好不同的并发客户端会反复释放/重载 sidecar，放大 H2；且一次“关闭”搜索会抑制 maintenance 的 6 小时重建。
2. **M4**（ipc.rs:789-804，UpdatePreferences 处理器第 799 行）：`let _ = indexer_client::search_with_options("", 1, None, pinyin_enabled).await;` 用空查询 Search 当 side-channel 下发开关；吞错误（`let _`）且可阻塞约 18 秒。
3. **unwrap_or(false) 默认翻转**（indexer_runtime.rs:1490，Search arm）：客户端省略 `pinyin_enabled` 时默认 `false` → 在 M6 bug 下会全局关闭拼音。

#### 改法（按计划已修正处方）

**协议层**：
- `lib.rs:42`：`INDEXER_PROTOCOL: u32 = 1 → 2`。
- `indexer_ipc.rs:13-38`：`IndexerRequest` 新增 `SetPinyinEnabled { enabled: bool }`（serde tag → `{"type":"set_pinyin_enabled","enabled":...}`）。
- **保留** `IndexerRequest::Search.pinyin_enabled: Option<bool>` 字段（前向兼容：老 broker 二进制仍能编译；新索引端忽略它做状态写）。这是降低 blast radius 的关键决策——broker 的 `search_with_options`/`search_in_root`（indexer_client.rs:394-416）签名与调用点（ipc.rs 多处：1191、1414-1421、1449、1476、1671-1685、1765、1909、1983）**无需改动**。

**索引端 search() 只读化**（indexer_runtime.rs:485-510）：
- 删除 `self.pinyin_enabled.store(pinyin_enabled, Ordering::Release)`（第 505 行）。
- 删除 `if pinyin_enabled { ensure_pinyin_loaded } else { release_pinyin }` 块（506-510）。
- `search()` 的 `pinyin_enabled: bool` 参数：**保留**但改为只读——用它决定本次搜索是否在结果里包含拼音匹配（读 `self.pinyin_enabled.load(Acquire)` 做只读判断），不再写全局标志。若参数省略（None），`handle_connection` 的默认从 `unwrap_or(false)` 改为 `state.pinyin_enabled.load(Ordering::Acquire)`（读已存储的偏好，而非强制 false）。

**索引端新增 SetPinyinEnabled arm**（indexer_runtime.rs:1460-1511，handle_connection）：
- 新增 `Ok(IndexerRequest::SetPinyinEnabled { enabled }) =>` 分支，走 `spawn_blocking`：
  - `enabled=true` → `state.pinyin_enabled.store(true, Release)` + 若索引就绪则 `ensure_pinyin_loaded(state)`（复用既有逻辑）；
  - `enabled=false` → `state.release_pinyin()`（既有方法，置 Disabled + 丢 sidecar）。
- 返回 `IndexerResponse::Status { ... }` 或新增一个轻量 ack（复用 `Status` 即可，避免再扩 `IndexerResponse`）。

**broker 端 UpdatePreferences**（ipc.rs:789-804）：
- 删除第 799 行 `let _ = indexer_client::search_with_options("", 1, None, pinyin_enabled).await;`。
- 新增 `indexer_client::set_pinyin_enabled(pinyin_enabled: bool)` 客户端辅助：走持久连接（复用 `connection_lock` + `handshake` + `exchange(&IndexerRequest::SetPinyinEnabled { enabled })`），带 `REQUEST_BUDGET` 超时。
- 调用改为：`if let Err(error) = indexer_client::set_pinyin_enabled(pinyin_enabled).await { log!(...) }`（M4 的“失败记日志”）。
- 可后台 `tokio::spawn` 但必须保住“disable 释放 / enable 加载”语义；由于开关切换频率极低（用户设置动作），直接 await + 短超时也完全可接受，比后台 spawn 更易保证语义。

**maintenance/checkpoint Disabled 语义**（indexer_runtime.rs:740-749、1293-1297）：
- **不动**。`release_pinyin()` 仍置 `PinyinStatus::Disabled`；maintenance（`:742`）和 checkpoint（`:1293`）的 `!= Disabled` 守卫照常工作。修正后 `release_pinyin()` 只由 `SetPinyinEnabled` arm 调用（显式用户动作），不再被每次 Search 触发，所以 `Disabled` 状态稳定，守卫行为正确。

#### INDEXER_PROTOCOL 1→2 的全部引用（已穷尽）
| 文件:行 | 用途 |
|---|---|
| `lib.rs:42` | 定义（改为 2）|
| `indexer_client.rs:38,183,187,458,463,676` | 握手发送+校验（值跟随常量，无需手改）|
| `indexer_runtime.rs:23,1446,2078` | 服务端 hello 校验+测试 raw hello（值跟随常量）|

bump 后老协议客户端在 `indexer_runtime.rs:1446` 和 `indexer_client.rs:187/463` 被拒——这是计划的“同仓同版发布，新旧混跑由 hello 校验拒连”预期行为。**必须 indexer 服务与 broker 同次重建同次安装**，否则握手失败。

#### 测试更新
- `indexer_ipc.rs:275-276`：`protocol: 1` 断言改 `2`。
- `indexer_runtime.rs:1583/1601`（Disabled 状态断言）：仍应通过（`release_pinyin` 仍置 Disabled，只是触发源变了）；补一个 `SetPinyinEnabled` arm 的单测（mock state，验证 enable→ensure_pinyin、disable→release_pinyin 调用路径）。
- `indexer_runtime.rs:2074`（`prompt_client_passes_hello` 发 `INDEXER_PROTOCOL`）：值跟随常量，无需手改。

#### WPF 前端影响
**无**。`Request::UpdatePreferences`（broker 协议，ipc.rs:137-140）不变，只改其处理器内部实现。前端只与 broker 通信，不直接说 indexer 协议，无需重新编译 C# 侧（仍会一起 build 验证）。

**风险**：中（协议 bump 是主要风险）。通过保留 `Search.pinyin_enabled` 字段 + 让 search 只读，blast radius 收窄到：`lib.rs` 一行常量、`indexer_ipc.rs` 一个 enum 变体、`indexer_runtime.rs` 的 search() 几行 + 一个新 arm、`ipc.rs` 的 UpdatePreferences 处理器几行、`indexer_client.rs` 一个新客户端辅助函数。
