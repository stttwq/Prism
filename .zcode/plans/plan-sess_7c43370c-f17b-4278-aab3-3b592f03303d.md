# 审计批次8：UI 美观与动画 实施方案

## 参考调研结论

**PowerToys Run（微软官方启动器）的关键技术路线：**
- `WindowStyle="None"` + `ResizeMode="NoResize"` + `SizeToContent="Height"`，**不用 AllowsTransparency**
- Win11 圆角通过 `DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_ROUND)` P/Invoke
- 窗口阴影由 DWM 系统边框帧自然提供，无需 DropShadowEffect
- 图标字体用 `Segoe Fluent Icons, Segoe MDL2 Assets` 回退栈（Win11 优先 Fluent，Win10 回退 MDL2）
- 文本字体用 Win11 系统主题资源

**Prism 当前状态（已完成的条目）：**
- U3（动作占位文案）：✅ 已在 `SearchHeader.xaml.cs:104` 实现
- A2（ActionPanel 同步化）：✅ 已在 `ActionPanel.xaml.cs` 实现 SynchronizeDisplayItems

**不在本批次范围：**
- A1①+U8（去 AllowsTransparency + Mica/Acrylic）—— 依赖"放弃 Win10"决策，manifest 声明支持 Win10，WindowStyle=None 在 Win10 无 DWM 阴影、20px Margin 点击穿透会变；归批次9
- A1③（动画期 SizeToContent 置 Manual 试点）—— 与 A1① 强耦合，一并推迟

## 实施条目（按风险从低到高排序）

### 第一组：快赢（≤1小时级，纯令牌/文案替换，零行为变化）

#### 1. U1 — 字体换代
- **文件**：`Tokens.Light.xaml:38`、`Tokens.Dark.xaml:39`
- **改动**：`AppFontFamily` 从 `微软雅黑, Segoe UI` → `Segoe UI Variable Text, 微软雅黑, Segoe UI`
- **Win10 回退**：Segoe UI Variable Text 仅 Win11 内置；Win10 无此字体自动回退到"微软雅黑"（font-family fallback 机制），与现状等价
- **影响面**：所有引用 `{DynamicResource AppFontFamily}` 的控件，纯字体名变化，布局不变

#### 2. U2 — 图标字体 Fluent 回退栈
- **文件**：`Tokens.Light.xaml` + `Tokens.Dark.xaml` 新增 `IconFontFamily` 令牌：`Segoe Fluent Icons, Segoe MDL2 Assets`
- **替换4处硬编码**（findstr 已定位）：
  - `SearchHeader.xaml:62` — 放大镜 `&#xE721;`
  - `ActionPanel.xaml:48` — 动作图标
  - `ActionPanel.xaml:90` — 子菜单箭头 `&#xE76C;`
  - `PinButton.xaml:24` — 固定按钮 `&#xE8A7;`
- **兼容性**：Fluent 是 MDL2 的超集，当前使用的码位（E721/E76C/E8A7）在两者中都存在，Win10 无 Fluent 字体时自动回退 MDL2，行为不变
- **WebIconProvider.cs** 不受影响（使用 DrawingImage 矢量绘制，非字体图标）

#### 3. U6 — 滚动条 hover 反馈
- **文件**：`Styles.xaml:28-59`（`PrismScrollBarThumb` + `PrismVerticalScrollBar`）
- **改动**：Thumb 模板加 Trigger——`IsMouseOver=True` 时 CornerRadius 从 2→3、Margin 从 1→0（变宽），同时背景色加深（用 `ScrollThumb` 令牌的 0.7 不透明度叠层）
- **影响面**：仅滚动条视觉，不影响布局/滚动行为

### 第二组：小项（低风险，局部视觉调整）

#### 4. U4 — 浅色 hover 可见性
- **文件**：`Styles.xaml:155-174`（ResultListBoxStyle 的 ListBoxItem 模板）+ `ActionPanel.xaml:163-182`（ActionPanel 的 ListBoxItem 模板，同构副本）
- **当前问题**：hover 时 `HighlightHover` 的 Opacity=0.55 × `BgItemSelected(#ECEEF0)` 叠白底 ≈ #F5F6F7，几乎不可见
- **改动**：hover Opacity 从 0.55→0.8（两处模板同步改），深色主题不受影响（#2E3033 × 0.8 仍然明显）
- **影响面**：仅 hover 视觉强度，不影响选中态/动画时长/任何交互逻辑

#### 5. U5 — 卡片 1px 边框
- **文件**：`SearchWindow.xaml:15-19`（Card Border）
- **改动**：加 `BorderBrush="{DynamicResource Divider}" BorderThickness="1"`
- **影响面**：Card 尺寸因 1px 边框微变，但 Margin=20 有充足余量；Clip 的 RectangleGeometry 需对应调整 RadiusX/RadiusY（已有 UpdateCardClip 方法动态计算，无需额外处理——Clip 用的是 ActualWidth/ActualHeight，边框已含在内）
- **注意**：深色主题下 Divider=#3C4043 在 #202124 底色上可见；浅色主题 Divider=#E8EAEC 在 #FFFFFF 底色上微可见——配合 DropShadowEffect 共同勾勒边界

#### 6. U7 — 右键菜单加图标列
- **文件**：`Styles.xaml:208-242`（`PrismContextMenuItemStyle`）+ `SearchWindow.xaml.cs:439`（构建 MenuItem 处）
- **改动**：
  - MenuItem 模板从单列 ContentPresenter 扩为两列：左列 24px 图标列 + 右列文字
  - 图标用 `IconGlyph`（ActionItem 已有此字段），通过 `MenuItem.Icon` 或模板绑定
  - IconGlyph 为空时图标列宽度收为 0（`DataTrigger Binding="{Binding IconGlyph}" Value="" → Collapse`）
  - `SearchWindow.xaml.cs:439` 处构建 MenuItem 时从 ActionItem 取 IconGlyph 设入
- **注意**：右键菜单的 actions 列表来自 `_vm.GetActionsForAsync(target)`，ActionItem 已有 IconGlyph 字段；节标题(IsSectionHeader)跳过图标

### 第三组：内存与动画（中等风险，需真机验证）

#### 7. A4 — 图标缓存策略 + 空闲 Trim 延迟
- **文件**：`IconCache.cs`、`SearchWindow.xaml.cs:309-328`（ReleaseIdleMemory）、`SearchWindow.xaml.cs:156-166`（IdleMemoryReleaseRequested）
- **当前问题**：每次隐藏窗口 → `_icons.Clear()` 全清 + `GC.Collect` + `EmptyWorkingSet`；下次呼出所有图标空白一帧起步
- **改动**：
  - `IconCache.Clear()` 改为 `ClearPathKeys()`：只清路径类键（完整路径、URL），保留 `ext:`/`dir:` 扩展名键（扩展名图标恒定，无内存膨胀风险，128 条上限已有 LRU 保护）
  - `ReleaseIdleMemory` 中 `_icons?.Clear()` → `_icons?.ClearPathKeys()`
  - `IdleMemoryReleaseRequested`（清空查询时触发）同理
  - `EmptyWorkingSet` + `GC.Collect` 从"每次隐藏"改为"隐藏后空闲 3 分钟一次性执行"：用 DispatcherTimer 延迟，再呼出则取消 timer
- **影响面**：图标缓存保留扩展名条目，下次呼出扩展名图标立即可见；路径类图标仍按需重新加载。TrimWorkingSet 延迟不影响功能，仅工作集回收时机变化
- **App.xaml.cs 的 3 处 TrimWorkingSet**（:141/:200/:340）保持不变——这些是启动/连接后/设置窗关闭的一次性 trim，不是高频路径

#### 8. A5 — 状态消息淡入
- **文件**：`SearchWindow.xaml.cs`（`ApplyState` 中 Divider 淡入已有）+ `ResultList.xaml.cs:154-167`（StatusMessage setter）+ `SearchWindow.xaml.cs:830-837`（SetActionStatus）
- **改动**：
  - `ResultList.StatusMessage` setter：Visibility 从 Collapsed→Visible 时加 100ms Opacity 淡入（从 0→1）；Visible→Collapsed 仍瞬时（防按键周期新闪烁）
  - `SetActionStatus`：同理，出现时淡入 100ms，消失瞬时
  - **关键约束**（来自 feedback-wpf-animation-gotchas）：StatusText 的高度必须参与 UpdateListHeight 计算，淡入期间不得提前 Collapsed——所以淡入只动 Opacity，不动 Visibility（Visibility 先设 Visible 再 BeginAnimation Opacity）
- **影响面**：仅状态消息出现时的视觉效果，不影响高度计算/布局/交互逻辑

### 第四组：动画补间（需真机验证观感）

#### 9. A3 — ScopeChip 列宽补间
- **文件**：`SearchHeader.xaml.cs:58-73`（SetScope 方法）
- **当前问题**：chip 滑入后输入框文字瞬移几十像素（注释已承认"不做"）
- **改动**：
  - chip 所在的 Grid ColumnDefinition Width 从 Auto 改为固定宽度（chip 可见时 Width=chip 预估宽度，不可见时 Width=0）
  - 对 Width 做 120ms 补间动画（GridLengthAnimation — WPF 无内置，需自写 GridLengthAnimation 或用 attached property 中转 double→GridLength）
  - 或替代方案：chip 内容做淡入+滑入（已有），但列宽固定不变（chip 不可见时列宽=0，可见时直接设为目标宽度不做动画，仅 chip 内容做淡入滑入）——此方案更简单，消除"瞬移"但无宽度过渡
  - **推荐用替代方案**（固定宽度+内容动画），因为 GridLengthAnimation 在 WPF 中实现复杂且易出 bug
- **影响面**：SearchHeader 布局；Grid 列定义改变可能影响其他列的可用宽度——但搜索框列是 `Width=*`，自适应

#### 10. A1② — 九宫格预渲染阴影缓存
- **文件**：`SearchWindow.xaml:15-26`（Card Border + DropShadowEffect）
- **当前问题**：DropShadowEffect 逐帧栅格化，即使 RenderingBias=Performance 仍是掉帧因素
- **改动**：
  - 预渲染阴影：按高度档位（62px 行高 ×N，N=0..9）生成 9 张阴影位图缓存，Card 高度变化时切换对应档位
  - 用 Border 的 Background 设为预渲染的阴影位图（比 Card 大一圈的 padding），替代 DropShadowEffect
  - 保留 DropShadowEffect 作为回退开关（配置项或编译开关），真机帧率对比后决定去留
- **影响面**：窗口外观（阴影视觉可能微变）；高度动画路径（每帧只切图不栅格化）；需真机对比验证
- **复杂度较高**：需实现位图生成+缓存+档位切换逻辑
