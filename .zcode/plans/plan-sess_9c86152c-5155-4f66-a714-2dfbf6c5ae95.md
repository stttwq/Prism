## 统一修复方案

### 问题 1：indexer 崩溃 — `validate()` 拒绝合法的"孤儿节点"状态

**根因**：`build_all()` 成功构建索引后，`index_cache::save()` 调用 `validate()` 验证完整性。但 USN replay 阶段可能产生"目录被删除但子节点仍标记为 present"的中间态——`delete()` 只清除目录自身的 `FLAG_PRESENT`，不级联到子节点。`validate()` 在 `hierarchy.rs:492` 检测到子节点的父目录不是"present directory"就返回 `Err`，导致整个服务崩溃。

**修复**：让 `validate()` 容忍孤儿节点——当父目录不存在时，将该子节点视为"隐式已删除"，跳过而非报错。这是安全的，因为搜索路径（`path_for()`）已经在运行时检查每个祖先的 `FLAG_PRESENT`，孤儿节点永远不会出现在搜索结果中，不会造成功能错误。

改动文件：`src/prism-core/src/hierarchy.rs`

```rust
// hierarchy.rs:492 — 改前：
if parent.flags & (FLAG_PRESENT | FLAG_DIRECTORY) != FLAG_PRESENT | FLAG_DIRECTORY {
    return Err(format!("cache parent is not a present directory: {record}"));
}

// 改后：父目录不存在（tombstoned）时跳过该节点，而非报错
if parent.flags & FLAG_PRESENT == 0 {
    // 父目录已被删除但子节点仍在——USN replay 的合法中间态。
    // 搜索路径在 path_for() 中会跳过这些节点，不影响功能。
    continue;
}
if parent.flags & FLAG_DIRECTORY == 0 {
    return Err(format!("cache parent is not a directory: {record}"));
}
```

只改 3 行，将"父目录不存在"从硬错误降级为跳过，同时保留"父节点存在但不是目录"的硬错误检查（这才是真正的数据损坏）。

### 问题 2：Prism.exe 崩溃 — `SetWinEventHook` 回调重入导致 Access Violation

**根因**：`ShowAndFocus()` 中 `Topmost = true → false → true` 三次切换时，`false` 让置顶的任务管理器短暂获得前台，触发 `EVENT_SYSTEM_FOREGROUND` 事件。回调在 WPF 窗口初始化期间被重入调度，回调先访问了 `IsVisible` 和 `WindowInteropHelper.Handle`（第 356 行），**之后**才检查 `_ignoreDeactivate` guard（第 357 行）。窗口句柄在创建过程中不稳定，导致 coreclr.dll 中的原生 Access Violation。

**修复（两处改动，互相独立）**：

**改动 A**：重排 `OnForegroundChanged` 回调——把 `_ignoreDeactivate` 和 `_hiding` guard 检查提到所有 WPF 状态访问之前，并缓存窗口句柄避免每次回调都创建 `WindowInteropHelper`。

改动文件：`src/Prism/Windows/SearchWindow.xaml.cs`

1. 新增字段 `private IntPtr _hwnd;`，在 `Loaded` 或 `SourceInitialized` 时缓存句柄
2. 回调改为：
```csharp
private void OnForegroundChanged(...)
{
    if (idObject != 0) return;
    // 先检查 guard，不碰任何 WPF 状态——避免窗口初始化期间的重入崩溃
    if (_ignoreDeactivate || _hiding) return;
    if (!IsVisible) return;
    if (hwnd != IntPtr.Zero && hwnd == _hwnd) return;
    if (!SearchWindowFocusPolicy.ShouldHide(...)) return;
    HideAnimated();
}
```

**改动 B**：移除 `Topmost = true → false → true` 三次切换，改为单次 `Topmost = true`。三次切换的本意是强制前台焦点，但 `ForceActivate()` 已经通过 `SetForegroundWindow` + `AttachThreadInput` 完成了前台获取。三次切换不仅多余，还是制造任务管理器前台闪烁的直接原因。

```csharp
// 改前（第 205-207 行）：
Topmost = true;
Topmost = false;
Topmost = true;

// 改后：
Topmost = true;
```

### 不改动的部分

- `delete()` 不做级联删除——递归删除子节点在大量文件的场景下性能差，且可能与"先删后移"的 USN 事件冲突
- `SetWinEventHook` 安装逻辑不变（构造函数中安装，WINEVENT_OUTOFCONTEXT | SKIPOWNPROCESS）
- 诊断日志系统不变（已验证有效）
- 现有测试不变（`validate()` 测试用例中的合法节点仍然通过，孤儿节点不再报错）
