# Prism 快捷键探索

> **文档性质:设想探索,非实施计划。** 闲聊中围绕"快速打开"这条核心路径发散的快捷键相关思考,供将来参考。
>
> 日期:2026-08-21
> 上下文:用户定位 Prism 的核心价值是"快速打开文件和应用,省去打开文件管理器→文件夹→文件的时间",围绕这条最短路径探讨怎么更顺更合手

## 核心路径

用户的典型操作链路只有三步:**双击 Ctrl → 打字 → Enter**。

所有快捷键设计的出发点:压这条链路的每一环,以及链路周边的高频动作。

## 心智模型:双通道分流

讨论中自然形成了一个干净的心智模型,它消解了"选择成本"问题:

- **常用文件走别名(显式)**:用户花一次成本设别名(weixin.exe → wx),之后每次两字母直达。别名精确触发、独立通道,第一个就是想要的,不用选。
- **不常用文件走搜索+history(隐式)**:不常用文件不会专门设别名(设了也记不住),但名字大概记得,搜一次 history 记住,下次更准。越用越准。

这个分流的边界是用户自己划的(愿不愿意设别名),不是系统强加的。常用文件根本不用选(别名直达第一),不常用文件本来就有心理预期要搜。选择成本被自然消解。

## 快捷键分层:全局 vs 窗口级

### 核心设计判断

**功能快捷键只在搜索窗口打开时生效,隐藏时不生效,避免变成全局快捷键。**

这个判断的依据:

- **全局快捷键是瘟疫**:跟所有软件抢键位,谁先注册谁赢,用户一脸懵。而且全局钩子常驻,即使 Prism 没开也在拦截按键,违背"安静"。
- **窗口级快捷键天然无此问题**:Prism 窗口关了快捷键就不存在,不抢任何人的;窗口开着它是焦点窗口,按键天然归它处理。WPF 的 KeyDown/PreviewKeyDown 就是窗口级,现有 Ctrl+1-9 打开结果、`→` 进动作面板走的就是这条路。新增快捷键只是往这条管道加绑定,不碰全局钩子。

### 两层划分

| 层级 | 内容 | 数量 | 备注 |
|---|---|---|---|
| **全局** | 仅呼出(双击 Ctrl) | 1 个 | 没法省——窗口还没出来,窗口级快捷键没法触发它。已有 60s 钩子自愈降级,已验证能共存 |
| **窗口级** | 其余所有(动作快捷键、Ctrl+数字、别名触发等) | 多个 | 窗口开着才生效,不抢键位不常驻 |

### 设置页映射

快捷键设置页里:全局那一项可能灰着不可改(或只允许改呼出方式),其余全是窗口级。用户一看就懂:这些只在 Prism 开着的时候管用。

## 高频动作快捷键化

### 问题

现在高频动作(打开所在文件夹、复制路径、压缩、重命名)得按 `→` 进动作面板再选,多两步。`→` 面板交互适合低频动作偶尔用,但高频动作值得直接快捷键,省掉面板那一跳。

### 候选映射(示例,可自定义)

| 快捷键 | 动作 | 现状 |
|---|---|---|
| Enter | 打开文件 | 已有 |
| Ctrl+1-9 | 打开第 N 个结果 | 已有 |
| `→` | 进动作面板 | 已有 |
| Ctrl+Enter | 打开所在文件夹 | 待加 |
| Ctrl+Shift+C | 复制路径 | 待加 |
| (可扩展) | 压缩、重命名等 | 待加 |

### 自定义范围

不做全量可配置(看起来强大但用户真正会改的就那几个),只把**高频动作**做成可配置,其余留在 `→` 动作面板里偶尔用。动作面板本来就是为低频动作设计的。

## 自定义快捷键:为什么即使自己用也有必要

Prism 是给作者自己用的工具,但设置页仍需完善。理由不是"给别人用",是**使用环境会变化**:

- 今天 Ctrl+Enter 合适,过阵子装了新软件冲突了,得能改
- 自定义不是为了"给别人用",是为了"适应自己变化"

这个理由站得住。

## 设置页架构:快捷键 + 别名同区域

快捷键和别名本质是同一件事的两种模态:

- **快捷键** = 按键 → 触发动作
- **别名** = 打字 → 触发文件

都是"用户自定义的加速通道",只是一个走键盘肌肉记忆,一个走搜索框文字。放同一个设置区域(比如叫"快速访问")心智统一。

但内部拆成两页或两个分组——数据形态不同:
- 快捷键是 `action → key` 一对一映射表
- 别名是 `path → [词列表]` 一对多

混在一个页面里 UI 会拧巴。

## 别名系统要点(详见 PRISM-FUTURE-DIRECTIONS-2026-08-20.md)

- 多词系统:`路径 → [词列表]`,一个文件可绑多个词
- 精确触发,独立通道,和字面搜索并行不合并
- 通道内 frecency 排序,冷启动按设置时间倒序
- 别名命中写同一条 history(frecency 反映真实使用频率)
- 路径失效静默降级(history stale paths 教训现成)
- 双入口:右键结果行"设置别名" + 设置界面统一管理

## 未定的点

- **打开后隐藏 vs 连续打开**:打开文件后 Prism 隐藏,单次操作没问题。但"搜出来三个文件都要开"场景下,需双击 Ctrl 重新呼出,查询状态是否保留待定。折中方案:打开后保持 1-2 秒再隐藏,给"还要开下一个"的窗口——但可能破坏单次操作的干净感,风险待评估。
- **MRU 空查询质量**:双击 Ctrl 呼出后空查询直接显示最近最常用,Ctrl+1 就开。这个 frecency 够不够准、敢不敢闭眼 Ctrl+1,依赖排序质量。
