# Prism 暂存区、工作集与拖拽

> **文档性质:设想探索,非实施计划。** 从"搜到文件然后呢"这个问题出发,推演出暂存区→工作集→拖拽三个紧密关联的方向。供将来参考。
>
> 日期:2026-08-21
> 上下文:拖拽是暂存区的前提,暂存区是工作集的工作台,三者是一条链上的东西

## 起点:搜到文件然后呢

Prism 的核心路径是"双击 Ctrl → 打字 → Enter",搜到文件直接打开。这条路径很快,也只解决"打开"这一件事。但搜到文件之后,人不一定只是打开——可能要把文件塞进邮件当附件,可能要拖进编辑器,可能要把几个文件凑在一起处理。

现在的动作面板(按 `→` 弹出来的那一列)覆盖了"选中后触发动作":打开所在文件夹、复制路径、压缩、重命名……这些都是"选中之后按一个键跑一个动作"。但有一种操作模式它覆盖不了——把搜索结果直接拖到别处去用。拖进邮件当附件、拖进文件夹复制、拖进聊天窗口发文件。这个交互动作面板管不了,因为它是"用身体记忆完成的操作",不是"选中再按键"。

拖拽是"搜到→处理"闭环缺的最后一环。

## 拖拽:只拖出去,不拖进来

### 为什么只拖出去

拖出去是"搜到文件→拖到别处用",这是闭环缺的一环。拖进来场景弱——搜索框是打字的地方,拖文件进来干嘛?除非拖进来自动填路径搜索,但那不如直接打字。

### 拖出去是上传还是复制

Prism 不判断,也判断不了。

从 Prism 拖一个文件出去,Prism 做的事情就是告诉 Windows"我这有几个文件,路径在这儿"。然后 Windows 把这个信息递给拖到的那个程序。至于那个程序拿这些路径干嘛,是它自己的事——拖到文件夹,文件夹就复制一份过去;拖到邮件,邮件就当附件夹上;拖到聊天窗口,就发出去;拖到网盘,就上传。

同一个动作,到了不同目标手里变成完全不同的事,Prism 没法提前知道用户准备拖去哪。拖出去的那一瞬间,目标还没确定——用户还在拖的路上。

### 只允许复制,不允许移动

Prism 拖出去明确是 Copy 语义,不允许 Move。意思是:你可以拿我的文件去用,但你不能把原文件搬走删掉。拖到文件夹复制一份没问题,但别把原文件删了。这个底线画好就行,剩下的是目标程序的自由。搜索结果不是文件所有者,不能让拖拽移动原文件。

### 一个一个拖

暂存区文件逐个拖,不做多选拖拽。

原因很实在:暂存区文件名横排成一行,一排小标签上 Ctrl 点几个再拖其中一个,这个手势别扭。横排标签的多选不像列表那么自然。而且"选中之后按住拖"和"选中"这两个动作怎么区分,在横排小标签上是个真问题——你 Ctrl 点了一下选中了,又按住想拖,到底是选中还是拖?

更重要的是,暂存区一共才五个文件,一个一个拖,每次拖一个,五次拖完。这个量级下手都不用多选,直接拖更快。多选拖拽在横排小标签上复杂度很高、收益很低。

市面上同类应用——FlowShelf、Tote、Dropover——全是"一个一个拖出去",没有一个搞多选拖的。这不是偷懒,是合理的取舍。

### 工作集整组拖是另一回事

暂存区一个一个拖,但工作集可以从档案柜列表里直接整组拖出去。工作集是明确圈定的一组文件,拖它就是拖整组,不存在"选哪几个"的问题。这个跟暂存区逐个拖不冲突,是两个出口各管各的:暂存区逐个拖满足日常,工作集整组拖满足"一把甩出去"的需求。

### 拖出去之后文件还在

拖出去不移除暂存区里的引用。暂存区是永久拿取口,不是一次性出库口。拖出去一百次,文件还在那儿。这跟"暂存"的意思一致——暂存就是放着,随时拿,拿不没。

### 拖拽时的窗口行为

Prism 失焦即隐。但拖拽时用户按住左键往窗外拖——鼠标离开 Prism 窗口,算不算失焦?如果算,拖到一半窗口消失了,拖拽就断了。

解法:拖拽进行中标记一下,失焦处理里检查这个标记,正在拖就不隐藏。拖完了再按原来的失焦逻辑走。

### 拖拽动画:轻,不加戏

拖起来那一刻,手底下有个东西跟着鼠标走,让你知道"我抓住了,在拖了"。这个 Windows 本身就会给一个半透明的影子跟着鼠标,不用自己加。

真想加一点 Prism 自己的味道,文件被拖走的那一刻在暂存区里变灰或者缩一下,告诉你"这个正在被拖"。轻的、快的、不打断手上动作的。

球状聚合这种花哨动画不做。拖拽讲究的是快——按住、走、松手,一气呵成,中间不能有东西挡着。每次拖东西都等它先变个戏法,久了烦。而且变成球之后,你看得见自己拖的是哪几个文件吗?

## 暂存区:唯一的工作台

### 是什么

暂存区是那个唯一的容器。搜到文件,往里扔;需要的时候,从里面拖出去用。始终可用,不依赖任何工作集。

### 为什么需要它

之前判断"搜到→处理"闭环已满(打开/复制路径/压缩/重命名全齐),但那都是"选中后触发动作"。拖拽是另一种模式——把文件拽到别处去用。拖拽需要一个出发的地方:你从哪开始拖?从搜索结果列表直接拖是一个办法,但搜索结果是临时的,翻页就没了。你需要一个稳定的地方放文件,放那儿随时能拖出去。

暂存区就是这个地方。它是"搜到文件→放在手边→需要时拖出去"这整条链的中间环节。

### 暂存区是当前工作集的工作台

暂存区绑定"当前工作集"这个角色。有工作集载入时,暂存区头上标着工作集名字:`暂存区（8月报告）`。没工作集时不标,就是暂存区本身。状态一眼分明,不靠记。

这个标只是说"你当前工作集是这个",不代表里面所有文件都属于它。角标才是真相——带角标的文件属于工作集,不带角标的是临时文件,两者视觉上分得清,在暂存区里混着放不冲突。

### 角标是真相

只有带角标的文件代表属于工作集,其余均属于暂存区本身。角标是唯一判断标准,暂存区名字不是。暂存区挂了工作集名字,视觉上暗示整块都是这个工作集的;但角标说里面只有部分文件属于工作集,临时文件就是临时文件。以角标为准。

### 排序:不分组,不隔,按扔进去的顺序

暂存区一共五个文件,一排全摊在眼前,靠角标区分谁是谁就够。不分组、不分隔、不排序,按你扔进去的先后顺序排。新文件永远接在最右边,东西待在你放的地方,不动。

分组的坏处:你往里扔一个临时文件,如果规则是"工作集文件排前面",那这一扔整个条可能要重排,文件在眼前跳来跳去。你刚刚还在读那个名字,一跳找不到了。按扔进去的顺序排,东西不动,这个"稳"比"整齐"更值钱。

### 拖拽是暂存区的前提

拖拽功能做不靠谱,暂存区那些设计全是空中楼阁。暂存区整个价值就是扔进去、拖出来用,拖这个动作做不好,暂存区就没意义。所以拖拽先做好,暂存区才有意义。

### 永久性

暂存区轻持久化——关 Prism 再开还在,像浏览器未保存的标签页。满了最早未标记的被挤掉(LRU),工作集文件挤不掉(已归档)。

### 数量上限

默认 5 个,可在设置中自定义调高。满了最早未标记的被挤掉,工作集文件挤不掉。默认小守安静,需要时放开。

### 外观

搜索框下方,结果列表上方,横向带状。空时收成几像素细线不占地方,有文件展开成一行高度,等于一行搜索结果的高度。

- 左边小数字,当前文件数
- 文件名横排,不显示完整路径(悬停 tooltip 显示),截断到能认出的长度
- 属于工作集的文件名带角标,没标记的不带
- 单字按钮:清空、存为工作集
- 工作集入口、设置入口
- 背景半透明,视觉权重低于搜索框和结果列表,余光可见不抢视线

### 操作

- **加文件**:搜到文件,选中按 `+` 或拖动,进暂存区(有活跃工作集自动标记)
- **用文件**:从暂存区拖出去到任意应用,或点击暂存区文件名打开
- **清空**:清空未标记文件(工作集文件不清,已归档)

## 工作集:档案柜

### 是什么

工作集是用户手动圈定的跨目录文件组,命名召回。暂存区是当前在干的那件事的工作台,工作集是收起来的档案柜。要换事,从档案柜里挑一个,点开看一眼里面是不是你要的,确认了再载入到暂存区。

### 为什么需要它

有些文件是跨目录的,但它们属于同一件事。比如"8月报告"那组文件:报告 DOCX 在 D 盘文档目录,数据 XLSX 在 D 盘数据目录,素材图片在另一个地方。你不会每次都去三个目录翻三遍,你需要一个"名字→文件组"的映射,打名字就召回整组。

### 工作集不锁死

工作集存完不锁死。工作是会发生变化的,文件是需要改动的。一个稳定不变的工作集是理想化的——实际工作里你后来往"8月报告"里加了份新数据,名字还是那个名字,但内容变了。这是正常的,不应该禁止。

### 工作集可加备注

默认工作集只显示名字和文件数量,点开才显示具体文件和备注。

备注不是把文件清单翻译一遍。文件清单已经能告诉你里面有什么文件了。备注写的是文件清单说不出来的东西——比如"老板要的那个版本,还差一张图"——这种状态、进度、上下文,文件名和文件清单都给不了你,这才是备注该干的事。

### 载入工作集时的保留规则

载入"9月报告"时:
1. 暂存区里属于"8月报告"的文件 → 移除引用(工作集档案不动,下次载入还在)
2. 暂存区未标记文件 → 保留(用户当前正在处理的,不能丢)
3. "9月报告"工作集文件 → 加入暂存区,标记为"9月报告"

结果:暂存区 = 未标记文件 + 新工作集文件。旧工作集从暂存区消失但没丢。

### 工作集之间的重叠

同一个文件可以属于多个工作集。文件本身不会因为被归进一个工作集就"属于"它——文件归文件,工作集归工作集,工作集只是一份"这些文件是一组"的记录,同一份记录可以指向同一个文件。

### 操作

- **存为工作集**:暂存区攒够,点存,起名,落盘归档
- **召回工作集**:搜索框打名字,结果列表显示整组;或从工作集入口载入到暂存区
- **直接拖出整组**:从工作集列表直接拖一个工作集出去,一次性把这组文件拖到目标应用,不需要先载入到暂存区

## 怎么实现

### 拖拽

拖拽是纯 UI 层操作,文件路径搜索结果里已有,不需要 broker 参与,不需要新协议。

用户从 Prism 拖文件出去,Prism 把文件路径列表交给 Windows(标准的 FileDrop 格式,资源管理器、邮件、聊天窗口都认),Windows 再递给目标程序。目标程序决定是复制、当附件还是上传。Prism 这边只声明 Copy 语义——只允许复制,不允许移动原文件。

触发拖拽靠鼠标位移阈值:按住左键移动超过系统默认的最小拖拽距离才算拖,否则算点击。这跟"单击选中"和"按住拖动"的区分是同一套判断。

### 暂存区

暂存区数据在内存里,关 Prism 再开还在(轻持久化)。文件在暂存区里存的是路径引用,不是文件本身——删暂存区里的条目不删原文件,原文件删了暂存区条目也不受影响(但下次拖出去会失效,这是路径引用的固有局限)。

暂存区始终可用,不依赖工作集。有活跃工作集时,往暂存区加的文件自动带工作集标记。用户的动作本身就是最准的信号——按 `+` 就是觉得该加,系统不用猜。这个"零摩擦加入"替代了"系统自动推荐",绕开了自动推荐质量撑不住的死结。

### 工作集

工作集落盘存储,挂在历史记录旁边,是一张"名字→路径列表"的标注表。存的时候记录文件路径列表和名字,载入的时候按路径列表召回。

工作集不锁死,可以加减文件。加减文件更新落盘记录。

### 统一存储

用户配的东西——呼出快捷键、动作快捷键、文件别名、工作集——都是"用户自己设的加速通道",存进同一套设置文件里。心智上统一:呼出是按键唤窗口,动作快捷键是按键跑动作,别名是打字直达文件,工作集是名字召回文件组。

## 对标产品

市面上有"文件架子"这个品类,验证了需求存在:

- **FlowShelf**(Windows, WinUI 3,微软商店在售):拖拽时滑出架子,把文件停在上面,再拖出去用,全程不碰磁盘。是一次性中转站,不持久化。
- **Tote**(Mac):菜单栏小图标,拖文件到图标上,再拖出去。单数操作,一个一个来。
- **Dropover**(Mac):虚拟架子,拖拽时弹出架子暂存文件。
- **Windows 11 "Drag Tray"**:Windows 11 测试过"拖到这里分享"弹层,短命,没保留。

这些全是独立工具,没有一个跟文件搜索绑在一起。Prism 的优势:搜到文件,顺手就搁架子上,不用切到另一个应用去操作。这是架子类应用做不到的闭环——它们只能暂存你拖进去的东西,但东西从哪来?你得先打开文件管理器找到文件再拖过来。Prism 帮你找到了,搁架子这一步是顺手的。

横排标签多选交互方面,Material Design 3 的 Chips 规范有一条:同一组标签,要么全是单选,要么全是多选,别混着来。这支持了暂存区不做多选的取舍——五个文件一个一个拖,简单不别扭。

## 和其他设想的关系

- **别名**:别名是 `路径 → [词]`,工作集是 `名字 → [路径列表]`,共用标注层
- **快捷键**:`+` 加入暂存区是窗口级快捷键,和其他高频动作快捷键同一套
- **多选**:暂存区吸收了多选拖拽的复杂度——一个一个扔进去,凑齐一起拖出去,不用 Ctrl 多选
