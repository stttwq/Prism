## 一、这次要测什么（先看懂这个，后面就顺了）

Prism 平常是**全局搜索**：你按快捷键呼出它，输入什么它就在整台电脑里找。

这次新做的功能叫**当前目录搜索**：如果你是从一个文件夹窗口里呼出 Prism 的，
它会自动"只在这个文件夹里面找"，不再翻整台电脑。

举个例子。你打开了 `文档` 文件夹，然后呼出 Prism 输入 `报告`：

- 旧的行为：整台电脑里所有叫"报告"的东西都列出来
- 新的行为：只列出 `文档` 文件夹（和它的子文件夹）里叫"报告"的东西

支持两种文件夹窗口：Windows 自带的**资源管理器**，和你电脑上装的 **Directory Opus**。

**你的任务**：把这个功能的每种情况都试一遍，看它表现对不对，把结果记下来。

> **为什么需要你手动测？** 这个功能要跟真实的窗口打交道——真的开窗口、真的切标签、
> 真的中途把窗口关掉。这些没法自动测，只能人来点。

## 二、开始之前

### 你需要知道的三个词

| 词 | 意思 |
| --- | --- |
| **呼出 Prism** | 让 Prism 的搜索框出现。默认是**快速按两下 Ctrl 键** |
| **范围标签** | 搜索框上方的一小块字，写着"当前目录：xxx"。它告诉你现在搜哪儿 |
| **回到全局搜索** | 范围标签消失了，Prism 又在整台电脑里找 |

### 一条贯穿全场的判断标准

**这个功能宁可不工作，也绝不能找错文件夹。**

所以整个测试里，只要你看到范围标签显示的路径**和你当时开的文件夹不一样**，
那就是严重问题，一定要记下来。而"它没认出来、老老实实回到全局搜索"——**这是正确行为**，不是 bug。

### 准备工作

1. 关掉所有 Prism 窗口（右下角托盘图标上右键退出）
2. 随便找个文件夹，里面**至少有几个文件和一个子文件夹**，测试时好操作
3. 准备一个记录的地方（记事本就行），把每一项的结果写下来

### 要测的程序在哪

用这个：

```
E:\LS\DM\listary\src\Prism\bin\Release\net8.0-windows\Prism.exe
```

双击它就能启动。

> ⚠️ **重要：光有这个 exe 还不够，后台服务也必须是新的。**
> Prism 分两半：你看到的搜索框（上面这个 exe），和一个在后台默默干活的**索引服务**。
> 「只搜当前文件夹」这件事**是后台服务干的**。如果服务是旧版本，
> 你会看到范围标签正常显示，但搜索结果还是整台电脑的——因为服务根本不认识"只搜这里"这个指令。
>
> 所以开测前**必须先更新服务**，做法见下一节。

## 三、第一步：更新后台服务（**必做，否则测了也白测**）

这一步需要**管理员权限**，所以得你自己操作。

### 为什么要做

后台服务负责真正的搜索。你电脑上现在装的那个是 8 月 1 日的旧版本，
它不认识"只搜当前文件夹"这个新指令——收到之后会当没看见，照样搜整台电脑。

表现出来就是：范围标签写着「当前目录：文档」，但结果里全是别的地方的文件。
（这正是第一次测试 E1 不通过的原因，不是功能坏了，是服务太旧。）

### 怎么做

1. 按 **Win 键**，输入 `powershell`
2. 在搜出来的"Windows PowerShell"上**右键** → **以管理员身份运行**
3. 弹出"是否允许此应用对你的设备进行更改"→ 点**是**
4. 把下面这段**整个复制**，粘贴到蓝色窗口里，按回车：

```powershell
Stop-Service PrismIndexer
Copy-Item "E:\LS\DM\listary\src\prism-core\target\release\prism-indexer-service.exe" `
          "C:\Program Files\Prism\prism-indexer-service.exe" -Force
Start-Service PrismIndexer
Get-Service PrismIndexer
```

5. 最后一行应该显示 `Running`，就成功了

### 确认真的换成新版了

在同一个窗口里粘贴这句，按回车：

```powershell
Select-String -Path "C:\Program Files\Prism\prism-indexer-service.exe" -Pattern "root_scope" -Encoding Byte -Quiet
```

显示 **True** = 新版本，可以开测了。
显示 **False** 或空 = 没换成功，别往下测了，告诉我。

> **出错怎么办**：如果提示"拒绝访问"，说明第 2 步没用管理员身份打开，重来一次。
> 如果提示"找不到文件"，把出错信息发我。

## 四、第二步：打开两个开关

新功能**默认是关着的**（因为还没验收，就是你现在要做的事）。所以先打开。

1. 启动 `Prism.exe`
2. 右下角托盘找到 Prism 图标，右键 → 设置

   - ☑ 识别 Directory Opus 当前目录（实验性 / 需兼容矩阵验收）
4. 同时确认这一行**也是打勾的**（它是总开关）：
   - ☑ 从文件管理器呼出时限定当前目录（含子目录，Ctrl+G 切换）
5. 点"保存"，关掉设置窗口

> **注意**：改完设置后，**下一次呼出**才生效。如果你改设置前已经呼出过 Prism，
> 先按 Esc 关掉再重新呼出。

2. 不关它，去设置里把两个勾**打上**，保存

4. 再打开一个文件夹窗口，重新呼出 Prism

**应该看到**：现在有范围标签了，显示"当前目录：你打开的那个文件夹名"。

2. 打开文件夹窗口，呼出 Prism

**应该看到**：没有范围标签；按 Ctrl+G 之后提示"当前目录搜索已在设置中关闭"。

**记录**：☐ 通过 / ☐ 不通过

## 五、第三步：测 Windows 资源管理器（7 项）

资源管理器就是你平时双击"此电脑"打开的那个窗口。

> ⚠️ **你这台机器上 Directory Opus 接管了默认文件管理器。**
> 也就是说双击文件夹、或者在运行框里敲 `explorer 路径`，打开的都是 **Opus**，不是资源管理器。
> 这一节要测的是**真正的 Windows 资源管理器**，请一律用 **Win+E** 打开它。
> （我自己在排查时就栽在这上面，用命令行开了半天窗口，开出来的全是 Opus。）

### E1 · 最基本的：能认出当前文件夹

1. 用 **Win+E** 打开资源管理器，进到 `文档` 文件夹（或任意有内容的文件夹）
2. **在这个窗口是当前活动窗口的状态下**，呼出 Prism
3. 输入几个字，搜点东西

**应该看到**：
- 范围标签显示「当前目录：文档」
- 搜索结果**只有这个文件夹和它子文件夹里的东西**，没有别处的

**怎么确认结果对**：随便挑一条结果，看它的路径是不是都在 `文档` 下面。

**记录**：☐ 通过 / ☐ 不通过

---

### E2 · 两个窗口不能串

这项在测"它认的是你正在用的那个窗口，而不是随便挑一个"。

1. 开**第一个**资源管理器窗口，进到 `文档`
2. 再开**第二个**资源管理器窗口，进到 `D:\`（或另一个明显不同的盘/文件夹）
3. 点一下**第一个**窗口（让它变成活动窗口），呼出 Prism → 看标签，按 Esc 关掉
4. 点一下**第二个**窗口，呼出 Prism → 看标签，按 Esc 关掉
5. 来回多做两次

**应该看到**：每次的范围标签都对应你**刚点的那个**窗口。

**这项要特别小心**：如果第 4 步显示的还是「文档」，那就是串了，**一定要记下来**。

**记录**：☐ 通过 / ☐ 不通过

---

### E3 · 多标签页（可能测不了，没关系）

Windows 11 的资源管理器可以像浏览器一样开多个标签页。

1. 在一个资源管理器窗口里开两个标签，分别停在两个不同文件夹
2. 切到其中一个标签，呼出 Prism 看范围标签

**两种结果都算通过**：
- ✅ 显示的是你正在看的那个标签的文件夹 → 完美
- ✅ 没有范围标签，回到全局搜索 → 也可以，它认不出就老实认输

**只有一种算不通过**：
- ❌ 显示的是**另一个标签**的文件夹 → 这是找错了，严重问题，必须记下来

**记录**：☐ 通过（认对了）/ ☐ 通过（认不出，回到全局）/ ☐ 不通过（认错标签了）

---

### E4 · 在原窗口里跳转文件夹

1. 打开资源管理器到某个有子文件夹的地方，呼出 Prism
2. 搜一个**文件夹**出来，选中它
3. 按 **Ctrl+Enter**

**应该看到**：**原来那个**资源管理器窗口跳转到了这个文件夹。

**不应该看到**：新开了一个窗口。（新开窗口算不通过）

**记录**：☐ 通过 / ☐ 不通过

---

### E5 · 在原窗口里定位文件

1. 同上呼出 Prism，这次搜一个**文件**出来，选中
2. 按 **Ctrl+Enter**

**应该看到**：原窗口进到这个文件所在的文件夹，并且**这个文件是选中/高亮状态**。

如果失败了，**Prism 的搜索结果应该还在**（不能自己关掉）。

**记录**：☐ 通过 / ☐ 不通过

---

### E6 · 按 Esc 不能影响别人

1. 打开资源管理器，记住它现在的样子（在哪个文件夹、选中了什么）
2. 呼出 Prism，随便输点字，然后按 **Esc**

**应该看到**：资源管理器**一点变化都没有**，还是原来的文件夹、原来的选中状态。

**记录**：☐ 通过 / ☐ 不通过

---

### E7 · 窗口中途关掉（这项最容易出问题，请认真测）

这是在测"原窗口突然没了，它会不会犯傻"。分两种情况：

**情况 A：呼出之前就关掉**

1. 打开一个资源管理器到 `文档`
2. 在它上面呼出 Prism，确认标签显示「当前目录：文档」
3. 按 Esc 关掉 Prism
4. **把这个资源管理器窗口关掉**
5. 现在呼出 Prism（此时前台是桌面或别的程序）

**应该看到**：没有范围标签，全局搜索。**绝对不能**还显示「当前目录：文档」。

**记录**：情况 A ☐ 通过 / ☐ 不通过

**情况 B：呼出之后立刻关掉**

这种情况**没法用鼠标测**——Prism 一旦失去焦点就自动隐藏，你点不到资源管理器的关闭按钮。
（这不是 bug，是呼出式搜索的正常行为。）

用这个脚本代劳：它先倒计时，给你时间呼出 Prism，然后自己去关窗口，全程不抢焦点。

1. 打开资源管理器到任意文件夹
2. 另开一个 PowerShell 窗口（不用管理员），粘贴这两行回车：

```powershell
cd E:\LS\DM\listary\artifacts\g4-test-build
.\close-host-later.ps1 -Seconds 10
```

3. 它会列出要关的窗口并开始倒数。**趁这 10 秒**切到资源管理器，呼出 Prism，
   输入几个字让它出结果，然后**手别动**
4. 倒数结束窗口自己关掉，看 Prism 的反应

**应该看到**：范围标签消失，回到全局搜索，提示「原窗口已关闭，已回到全局搜索」。

**不应该看到**：还显示原来那个目录的范围标签，或搜索仍限定在已经不存在的目录里。

**记录**：情况 B ☐ 通过 / ☐ 不通过

> 测 Opus 的同一项（矩阵 O5）时把命令换成
> `.\close-host-later.ps1 -HostKind Opus -Seconds 10`。

## 十、几个可能让你困惑的地方

**Q：范围标签一直不出现，是坏了吗？**

先按顺序确认：① 两个"识别…当前目录"的勾打了吗；② 总开关打了吗；
③ 改完设置有没有先按 Esc 再重新呼出（改设置后要下一次呼出才生效）；
④ 呼出的时候，文件夹窗口是不是**当前活动窗口**（不能是最小化的，也不能你正在用别的程序）。

**Q：它经常认不出来，回到全局搜索，算通过吗？**

单看一项，"认不出→回到全局"算通过。但如果**大部分项目都认不出**，
说明识别成功率太低，这个也要告诉我——记下来大概几次里能成一次。

**Q：Ctrl+Enter 没反应？**

先确认你**选中了**一条结果（用上下箭头选，有高亮）。没选中时按 Ctrl+Enter 是没反应的。

**Q：测的过程中 Prism 崩了 / 卡住了？**

这是重要问题。记下你崩之前在做什么，然后重新启动 exe 接着测。

**Q：能不能只测资源管理器，不测 Opus？**

可以，两个是各自独立的开关，测完一个就能开一个。但两个都测完，G4 才算完整验收。

## 附：一页速查

```
呼出 Prism        双击 Ctrl
关掉搜索框        Esc
切换搜索范围      Ctrl+G（或用鼠标点范围标签）
在原窗口里打开    Ctrl+Enter（要先用箭头选中一条）
普通打开          Enter

要测的程序        src\Prism\bin\Release\net8.0-windows\Prism.exe
                  （不要自己重新编译）

两个开关          设置 → 常规 → "识别 Windows 资源管理器当前目录"
                              "识别 Directory Opus 当前目录"
总开关            设置 → 常规 → "从文件管理器呼出时限定当前目录"

改了设置          要先 Esc 关掉搜索框，下一次呼出才生效

最重要的一条      认不出来 → 正常
                  认错文件夹 → 严重问题，必须记录
```
